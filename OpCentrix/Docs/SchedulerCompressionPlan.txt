PHASE A SUMMARY (COMPRESSION) – CURRENT IMPLEMENTATION
============================================================
Goal: Pack SLS jobs on a machine forward to earliest feasible start times.
Key Behaviors Implemented:
  - 3h base setup between consecutive jobs (BaseSetupHours=3)
  - Additional material changeover delay when material differs (Job.CalculatePowderChangeoverTime)
  - Shift alignment (start must be inside a shift and not before shiftStart+BaseSetup)
  - 15-minute rounding
  - Full page reload on success (ensures job block geometry recalculation)
  - Logging prefix [COMPRESS-*]
Pending Enhancements:
  - Synthetic changeover block rendering (TODO-SLS-CHANGEOVER-BLOCK)
  - Option to disallow spanning outside shift (future flag)
  - Respect locked jobs / statuses (TODO-SLS-LOCKS)
  - Priority-aware reordering (TODO-SLS-REORDER)

QA Checklist (Compression):
  [ ] No "SSL" tokens

  [ ] Start never before horizonStartUtc
  [ ] Material changeover added only when material differs
  [ ] Base 3h always applied between consecutive jobs
  [ ] Shift alignment enforced (candidate within shift; fallback adds base setup if no shifts)

PHASE B PLAN: UPSTREAM (PREDECESSOR) JOB SUPPORT (MVP)
============================================================
Objectives:
  - Enforce that a job cannot start before all defined upstream jobs have finished + gap.
  - Allow user to define a single predecessor first (leveraging existing Job.PredecessorJobId).
  - Provide optional gap hours (buffer) between predecessor end and downstream start.
  - Modify compression to honor earliest-ready constraint (EarliestReady = predecessor.End + Gap, if later than current candidate).
  - UI affordance: add predecessor selection in job modal.

Phase B.1 (Single Predecessor):
Data Changes:
  - Add Job.UpstreamGapHours (double? default null => treat as 0).
  - Keep Job.PredecessorJobId (already present) as the single upstream reference.

Service Changes:
  - Extend ScheduleCompressionService logic:
      earliestReady = predecessor.ScheduledEnd (+ gap)
      candidate = max(candidate, earliestReady)
  - If earliestReady pushes job later, allow push (dependency precedence overrides compression pull forward).

Validation Rules (Single Predecessor):
  - Cannot set predecessor to self.
  - If predecessor chain loops (A->B then B->A) detect and reject.
  - When saving downstream job: if ScheduledStart < predecessor.ScheduledEnd + gap => auto-adjust or return validation message.

UI Changes (MVP):
  - Job modal: New collapsible section "Upstream Dependency" with:
      * Dropdown (searchable) of eligible jobs (Status: Scheduled/Building/Completed, excluding self & descendants).
      * Numeric input: Gap (hours, min 0, step 0.25).
      * Display read-only earliest-ready time preview.
  - Job block tooltip: append "Upstream: {PartNumber} ends {End:MMM dd HH:mm} (+{Gap}h)" when set.
  - Job block icon: small link chain glyph to signal dependency.

Compression Flow Update (Pseudo):
  previousJob logic (material + base) -> candidate
  if job.PredecessorJobId != null:
      load pred
      earliestReady = pred.ScheduledEnd + (job.UpstreamGapHours ?? 0) hours
      candidate = max(candidate, earliestReady)
  align with shift (if candidate now outside shift, advance as today)
  finalize start/end

Edge Cases (Single):
  - Predecessor scheduled after downstream (bad order): compression will push downstream forward automatically.
  - Predecessor on different machine: still enforce chronological dependency; base setup & material changeover only within same-machine sequential chain.
  - Deleted predecessor: null out PredecessorJobId + UpstreamGapHours.

Testing (Single):
  1. No predecessor -> unchanged behavior.
  2. Predecessor ends earlier than candidate -> unaffected.
  3. Predecessor ends later -> job delayed to earliestReady.
  4. Gap inserted pushes into next shift -> shift align and round-up.
  5. Chain A->B->C ensures transitive order after compression.
  6. Cross-machine dependency enforced (B on Machine2 waits for A on Machine1).

Phase B.2 (Preparation for Multi-Upstream):
  - Introduce IScheduleDependencyService with:
      BuildGraphAsync(jobIds)
      GetEarliestReadyUtc(job, graph)
      DetectCycles(graph)
  - Initially graph contains at most one edge per job.
  - Refactor compression to use dependency service so multi-upstream is a drop-in change.

PHASE C PLAN: MULTI-UPSTREAM & ADVANCED FEATURES
============================================================
Data Migration:
  - New table JobDependency (Id, JobId, UpstreamJobId, GapMinutes, CreatedUtc, CreatedBy).
  - Migration script: for each job with PredecessorJobId -> create JobDependency.
  - Keep legacy fields for back-compat until fully removed.

Scheduling Adjustments:
  - EarliestReady = MAX over all upstream (UpstreamEnd + GapMinutes).
  - Topological sort (Kahn). On cycle: log warning, remove offending edge(s).
  - Chain compression: method CompressChainAsync(rootJobId) (affects downstream set only).

UI (Multi-Upstream):
  - Upstream list with add/remove pills.
  - Gap edit inline per upstream.
  - Warnings on cycle attempt.

Additional Enhancements:
  - Critical path highlighting (longest upstream chain).
  - Risk flag if earliestReady > CustomerDueDate - buffer.
  - Drag & drop reorder writes ephemeral dependency (optional future).
